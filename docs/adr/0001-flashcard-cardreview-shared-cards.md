# 낱말카드: 카드는 단일본, SRS 상태만 사용자별

낱말카드 학습은 SRS(간격 반복)를 사용하므로 사용자별 학습 진도(ease, interval, next_review_at)가 필요하다. 이 진도를 어디에 저장할지가 데이터 모델 전체를 결정한다. **결정**: `Card` row는 덱당 단일본으로 모든 학습자가 공유하고, 사용자별 진도는 `CardReview(user_id, card_id, …)` 조인 테이블에 저장한다. **공식 덱·클럽 덱을 학습하기 위해 fork(개인 복제)는 요구하지 않는다** — fork는 카드 내용을 자신의 식대로 수정·추가하고 싶을 때만 사용하는 별개 행동이다.

## Considered Options

- **A. 단일 카드 + `CardReview` 조인 (채택)** — 카드는 한 벌, 진도는 사용자별. 학습자는 접근 가능한 덱을 원본 그대로 학습.
- **B. 학습 시 강제 fork** — 사용자가 공식 덱을 학습하면 자동으로 카드 N장이 그 사용자 소유로 복제되고, 그 복사본 위에 진도가 쌓인다. (Anki의 deck 다운로드 모델, Quizlet의 "Add to your sets" 모델에 가깝다.)
- **C. 카드 자체에 SRS 컬럼** — 즉시 탈락. 다중 사용자 학습 불가능.

B를 기각한 이유:
- **DB 폭증**: 공식 덱을 1만 명이 학습하면 카드 row가 1만 배로 복제된다.
- **콘텐츠 전파 단절**: admin이 룰 오류를 수정해도 이미 학습 시작한 사용자의 복사본은 그대로다. 학습 콘텐츠는 본질적으로 "지속적으로 다듬어지는" 것이라 이 단절이 치명적이다.
- **모더레이션 한계**: 부적절한 카드를 admin이 삭제해도 복사본은 남는다.

## Consequences

- 공식·클럽 카드의 텍스트가 수정되면 **이미 그 카드를 학습 중인 사용자의 `CardReview.ease`는 그대로 유지된다**. 즉 admin이 "쉬운 카드를 어렵게 갈아엎는" 행위는 사용자 학습 곡선을 왜곡할 수 있다. 카드 의미를 근본적으로 바꿔야 한다면 운영 가이드상 "새 카드 추가 + 기존 카드 삭제"로 처리한다.
- 카드 삭제 시 관련 `CardReview` row는 cascade delete 된다. 사용자 진도 보존이 필요해지면 별도 처리(soft delete + 진도 보존 마이그레이션)가 필요하다.
- Fork 시 원본 카드의 `CardReview` 상태는 fork된 새 카드로 **복사하지 않는다**. Fork 후 카드 내용을 수정할 거라 기존 ease가 의미를 잃기 때문이다.
- "카드 버전 관리"는 의도적으로 도입하지 않는다 (YAGNI). 진짜로 필요해지면 별도 ADR로 카드 버저닝 도입을 다룬다.
