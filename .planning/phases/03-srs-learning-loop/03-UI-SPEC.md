# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: SRS Learning Loop. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Design System Note: Phase 3 starter files (show.html.erb, _card.html.erb, complete.html.erb) use
> Tailwind CSS 4 utility classes per Decision D-23 (no full rewrite). All new study/browse view markup
> must also use Tailwind utilities to stay consistent within these views. Color values are anchored to
> the app-wide --hcp-* palette so the study area does not diverge visually from the rest of the app.

## Interaction Contracts (Stimulus)

### study_session_controller.js

| Behavior | Contract |
|----------|----------|
| Initial state | Back text hidden (`hidden`), rating buttons row hidden (`hidden`), "답 보기" button visible |
| Flip trigger | Click "답 보기" button → toggle `data-flipped=true` → back visible, rating row visible, "답 보기" button hidden |
| Keyboard 1/2/3/4 | Only fire when `data-flipped=true`; dispatch rating form submit for corresponding button; guard against pre-flip keypresses |
| Double-click guard | On rating button click: immediately add `disabled` attribute to ALL 4 rating buttons; Turbo Stream response replaces `#study-card` DOM including fresh unflipped card — no manual re-enable needed |
| Turbo Stream reset | New `#study-card` content from server always renders in unflipped initial state (back hidden, rating row hidden, "답 보기" visible) |
| Keyboard hint row | Render `<kbd>1</kbd>` through `<kbd>4</kbd>` labels below each button; visible only after flip (`data-flipped=true` sibling state or same toggle) |

### browse_controller.js

| Behavior | Contract |
|----------|----------|
| Card data | Loaded from `data-browse-cards-value` (Stimulus Array value) — JSON array of `{id, front, back}` objects |
| Initial state | Back hidden, index=0, prev button disabled |
| Flip trigger | Click "답 보기" button → show back, hide "답 보기" button (same UX as study, no rating buttons) |
| Next card | Click "다음" button → index++, reset to unflipped state, update counter display |
| Prev card | Click "이전" button → index--, reset to unflipped state, update counter display |
| Shuffle toggle | Click "셔플" button → Fisher-Yates shuffle on cards array → reset to index=0, unflipped; button label toggles active state |
| Counter display | "N / 전체 M" format, updates on card navigation |
| Empty deck | Browse controller renders "이 덱에 카드가 없습니다. 카드를 추가하면 여기에 표시됩니다." inline if cards array is empty |

## Accessibility Contract (WCAG 2.1 AA)

| Element | Requirement |
|---------|-------------|
| Rating buttons | `aria-label="다시 (1)"`, `aria-label="어려움 (2)"`, `aria-label="보통 (3)"`, `aria-label="쉬움 (4)"` |
| "답 보기" button | `aria-expanded="false"` (before flip) / `aria-expanded="true"` (after flip) |
| Back text panel | `aria-live="polite"` — screen reader announces when revealed |
| Rating button disabled state | `disabled` attribute + `aria-disabled="true"` during double-click guard |
| Browse card navigation | `aria-label="이전 카드"` / `aria-label="다음 카드"` on nav buttons |
| Card counter | `aria-live="polite"` so screen readers announce position change |
| Keyboard focus order | 답 보기 → (after flip) 다시 → 어려움 → 보통 → 쉬움 |
| Touch targets | All interactive buttons minimum 44x44px |
